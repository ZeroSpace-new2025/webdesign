## 三、实现路径

### 1. 登录（唯一免鉴权接口）

```
POST /api/v1/user/auth/login（白名单）{ employeeNo, password }
  → ApiAuthController.login → AuthService.login(employeeNo, rawPassword)
  → AuthServiceImpl
       1) findWithRolesByEmployeeNoIgnoreCase（含角色）→ 查不到统一提示“工号或密码错误”
       2) assertLoginable：DISABLED / LOCKED → 40300（提示联系管理员）
       3) BCrypt passwordEncoder.matches(rawPassword, user.password)
       4) toCurrentUser：角色 → permission_list 位图 → 展开 permCodes（含角色名）
       5) JwtCodec.sign(HS256)：载荷 = userId/employeeNo/name/deptId/roles/permCodes/iat/exp
  → LoginVO(token, expiresIn, expiresAt, userInfo)
  → 前端 login.js：localStorage.dsh_token + Cookie dsh_token → 跳 /portal
```

### 2. 每次请求的鉴权（公共链路）

```
AuthInterceptor.preHandle
  → resolveToken：Authorization: Bearer → token 头 → Cookie dsh_token
  → AuthService.verifyToken(token)
       · 黑名单（登出 / 改密后拉黑当前令牌）→ 40100
       · passwordChangedAt：改密后旧 token 失效 → 40100
       · 按 userId 回查库：账号不存在、状态非 ACTIVE（停用/锁定）→ 40100
       · roles / permCodes 取库里的当前值（令牌里的只是签发时快照，不能当授权依据）
       · 返回 UserContext(userId, employeeNo, name, deptId, workstation, phone, roles, permCodes)
  → UserContextHolder.set(context)
  → 页面请求未登录 → 302 /login；/api/** 保持 JSON 语义
  → @RequiresPerm：权限点任一命中或角色命中放行，否则 40300
```

> **为什么每次请求都回查库**：JWT 是自包含的，若直接信任载荷里的 `roles` / `permCodes`，
> 停用账号或撤销角色权限后，已签发的令牌仍能用到自然过期（默认 12 小时）。
> 代价是每个已登录请求多一次主键查询，换来“账号停用 / 权限变更立即生效”。
>
> 令牌载荷里另有随机 `jti`：时间字段只有秒级精度，同一秒内为同一用户签发的令牌会完全相同，
> 而黑名单按令牌字符串记账——没有 `jti` 时“登出后立刻重新登录”拿到的新令牌会命中旧黑名单，
> 表现为刚登录就 40100。

登出：`POST /api/v1/user/auth/logout` → `AuthService.logout` 把 token 放入进程内黑名单（单实例够用）。

### 3. 当前用户 / 修改密码

```
GET /api/v1/user/auth/me → AuthService.currentUser(userId)
  → findWithRolesById → toCurrentUser（角色 + 展开后的权限点）
PUT /api/v1/user/auth/password { oldPassword, newPassword }
  → AuthServiceImpl.changePassword：旧密码校验、新密码长度 ≥ 6、与旧密码不同
  → 更新 BCrypt 密码 + 记录 passwordChangedAt（让旧 token 立即失效）
  → 控制器随后调用 AuthService.logout(当前 Authorization 头)：把本次调用所用的令牌直接拉黑，
    避免“同一秒内签发”的令牌因秒级时间戳比较而漏网
```

### 4. 员工维护（页面 `/console` 员工管理视图 + 接口）

```
POST/GET/PUT/DELETE /api/v1/user/users[/{userId}]、PUT /users/{userId}/status、PUT /users/{userId}/roles
  → UserService.create / page / getById / update / disable / changeStatus / assignRoles
  → UserServiceImpl
       · create：工号唯一（40901）、手机号唯一且格式校验、BCrypt 初始密码（默认 123456）、
                 部门/工位落库、解析角色集合 → save → UserUpdatedEvent
       · page：UserRepository.search(keyword, deptId, workstation, status) → PageResult<UserVO>
       · update/disable/changeStatus：重新加载（含角色）→ 保存 → UserUpdatedEvent
       · assignRoles：resolveRoles → user.roles 覆盖 → UserUpdatedEvent
  → users + user_role
```

### 5. 批量导入员工

```
GET /api/v1/user/users/import/template → UserService.exportImportTemplate（CSV 模板，TabularExport）
POST /api/v1/user/users/import（multipart file, deptId?, roleIds?）
  → UserService.importFromExcel → UserServiceImpl
       1) UserImportParser.readRows(file)：解析 .xlsx / .csv 为字符串矩阵（不引第三方库）
       2) parseHeader + buildHeaderAliases：兼容中英文列名
       3) 逐行 toCreateCmd → create(cmd)；异常行收集到 ImportRowError（行号 + 原因）
       4) 返回 ImportResultVO(successCount, failedCount, errors[])
```

### 6. 角色与权限

```
POST/GET/PUT/DELETE /api/v1/user/roles[/{roleId}]、GET /permissions、PUT /roles/{roleId}/permissions
  → RoleService.create / page / update / delete / listPermissions / updatePermissions / getPermissions
  → RoleServiceImpl
       · 预置角色（RoleCodes.isPreset）不可改名、不可删除；有用户关联也不可删（40902）
       · updatePermissions：normalizeCodes（只保留 PermissionEnum 中的 permCode）→ PermissionList 位图
       · 保存后发布 RolePermissionChangedEvent（暂无订阅方；鉴权已改为每请求查库，不依赖事件失效）
  → role.permission_list
```

### 7. 月度销售报表（缓存表）

```
POST /api/v1/user/reports/monthly/generate { month, force }
  → ReportService.generateMonthly(month, force)
  → ReportServiceImpl
       1) assertReportPermission：FINANCE / MANAGER 角色，或 report:view / audit:view
       2) force=false 且缓存已存在 → 直接返回 reportId（幂等）
       3) rebuild：MonthlyOrderReader 按日调 OrderQueryService.page 取当月有效订单（含明细）
            → 按 菜品（recipeId）聚合 quantity / amount
       4) 覆盖写 monthly_report + monthly_report_item（report_month 唯一）
       5) 发布 MonthlyReportGeneratedEvent(month, reportId)
GET /api/v1/user/reports/monthly { month, deptId }
  → getMonthly：优先读缓存（缺失则同步生成）；deptId 非空时按员工部门过滤明细
POST /api/v1/user/reports/monthly/refresh → refreshMonthly(month)（force 重算）
GET /api/v1/user/reports/months → listReportMonths（月份选择器数据源）
```

### 8. 报表导出

```
GET /api/v1/user/reports/monthly/export { month, format=XLSX|CSV }
  → ReportService.exportMonthly(month, ExportFormat)
  → TabularExport.xlsx（SpreadsheetML）/ csv（UTF-8 BOM）
  → 文件名 “yyyy-MM-月度销售报表”，PDF 未实现 → 40001
```

### 9. 员工消费审计（实时聚合，不落库）

```
GET /api/v1/user/reports/employee-consumption { employeeId, month, withDetails }
  → ConsumptionAuditService.auditEmployee
  → ConsumptionAuditServiceImpl
       1) assertAuditPermission：FINANCE / MANAGER，或 audit:view / report:view
       2) UserService.getBrief 补姓名/部门/工位
       3) MonthlyOrderReader.readMonth(month, {employeeId}) → 当月有效订单
       4) 汇总 orderCount / totalQuantity / totalAmount；withDetails 时附明细（最多 100 张）

GET /api/v1/user/reports/dept-consumption { month, deptIds[] }
  → sumByDept：按 UserService.listByIds 的 dept_id 分组汇总

页面 /reports/monthly（员工月度消费报表）
  → MonthlyConsumptionPageController.page
  → ConsumptionAuditService.sumByEmployee(month, deptId)（一人一行：就餐天数/订单数/份数/金额）
  → 视图 report/monthly-consumption.html（月份切换、关键字筛选、下钻）
GET /reports/monthly/export → 同一份汇总表 CSV（TabularExport，末行合计）
GET /reports/monthly/employees/{id} → auditEmployee(withDetails=true) → report/employee-consumption.html
```

### 10. 页面入口：登录页 / 总门户 / 控制台

```
GET /login（白名单）→ PageController.login → login.html（login.js 调登录接口）

```

## 六、跨模块依赖与事件

| 方向 | 对象 | 用途 |
| --- | --- | --- |
| 调用 M2 | `OrderQueryService.page` / `getDetail`（经 `MonthlyOrderReader`） | 报表与消费审计取数（禁止直查订单表） |
| 调用 M2 | `OrderStatisticsService.monthlySummary`（页面展示） | 个人月度消费（M2 页面用） |
| 本模块内 | `UserService.listByIds/getBrief` | 补部门归属、员工信息 |
| 发布事件 | `UserUpdatedEvent`、`RolePermissionChangedEvent`、`MonthlyReportGeneratedEvent` | 目前**没有订阅方**，只作扩展点保留。鉴权已不依赖“事件让缓存失效”：`verifyToken` 每次请求回查库里的账号状态与角色权限，因此停用账号、撤销权限点即时生效 |
| 订阅事件 | 无 | 本模块不订阅其他模块的事件（报表按需生成/手动刷新） |
| 被其他模块调用 | `AuthService.verifyToken` / `checkPermission`、`UserService.listByIds` / `getBrief` / `hasAnyRole` | 认证拦截器、M2 越权校验、M3/M4 补员工信息 |

## 七、关键不变量

1. **认证唯一路径**：`users` 表 + BCrypt + JWT；无注册、无硬编码管理员。
2. **权限点单一来源**：`PermissionEnum`；角色权限存 `role.permission_list` 位图。
3. **报表取数边界**：M4 只能经 `OrderQueryService` 看订单，不直接访问 `order_form`/`order_detail`。
4. **报表是快照，不自动失效**：`monthly_report` 按 `report_month` 唯一，`force=true` 覆盖写；
   订单变更后报表不会自己重算，需要手动刷新（页面刷新按钮 / `POST /api/v1/user/reports/monthly/refresh`）。
5. **审计实时聚合**：员工/部门消费审计不落库，按需从订单快照现算。
6. **已知进程内状态**：JWT 黑名单与 `passwordChangedAt` 是进程内 Map，多实例部署需换 Redis（见 `AGENTS.md` 6.3）。

## 八、验证方式

- 自动化用例：`.\gradlew.bat test --tests "*AuthTokenStatusTests" --console=plain`
  （停用账号后旧令牌失效、撤销权限点后旧令牌立即降权、同秒登出再登录仍可用），
  `--tests "*JwtCodecTests"`（令牌唯一性 jti、篡改拒绝）。
- `./gradlew build`；dev 启动后 `manager/admin123` 登录 → 控制台新增员工/角色 → 批量导入模板下载与上传 →
  生成月度报表并导出 CSV；`finance/finance123` 登录 → `/reports/monthly` 看员工消费并下载 CSV。
- 边界：旧 token 在改密/登出后应 40100；普通员工访问 `/reports/monthly`、`/console` 应 40300（页面渲染无权限提示）；
  非财务/经理调用 `/reports/*` 接口应 40300。
