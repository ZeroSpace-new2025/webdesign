# M1 菜品与菜单中心 · 实现路径

> 负责“卖什么”：维护菜品库（食谱），从菜品库编排菜单、发布/下架/复用历史菜单，并为下单提供**冻结快照价**。
> 需求映射：`root_demend.md` 功能 1（食谱增删查改 + 图片）、功能 2（菜单生成/改名/改价/历史留存与复用）、
> 功能 7（内部食谱由餐厅经理和厨房主管管理）；页面设计见 `demand.md` M1 章节。

## 三、实现路径

### 1. 菜品列表 / 查询

```
页面 GET /recipes（或 API GET /api/v1/menu/recipes）
  → RecipePageController.list / ApiRecipeController.page
  → RecipeService.page(RecipeQuery)
  → RecipeServiceImpl.page
       · buildSpecification：名称模糊 like、分类（名称或派生 categoryId）、状态、价格区间
       · Sort by recipe_id DESC，PageResult.from
  → RecipeRepository.findAll(Specification, Pageable) → recipe
  → 视图 recipe/list.html（卡片 + 表格 + 分页汇总） / Result<PageResult<RecipeVO>>
```

历史菜品：`GET /recipes/history` → 同一 `page`，`status=DISABLED`（页面只读，用于追溯下架原因）。

### 2. 新增 / 编辑菜品

```
GET /recipes/new、GET /recipes/{id}/edit → RecipePageController.newForm / editForm → 视图 recipe/form.html（RecipeForm）
POST /recipes/save（multipart，含 imageFile）→ RecipePageController.save
  → RecipeService.create / update
  → RecipeServiceImpl
       1) 名称非空 + 唯一（existsByRecipeName / existsByRecipeNameAndRecipeIdNot → 40901）
       2) 分类：resolveCategory(category, categoryId)，categoryId 是分类名稳定哈希
       3) 单价 ≥ 0；单位/描述 trim；状态 ACTIVE/DISABLED
       4) 编辑时 checkVersion(@Version，冲突 40902)
       5) 有图片 → uploadImage(file) → ImageStorage.store → 返回 /uploads/xxx
       → save / saveAndFlush → 发布 RecipeChangedEvent(recipeId, UPDATED)
  → RedirectAttributes 回列表页
```

> `RecipeForm` 与 `RecipeCreateCmd/RecipeUpdateCmd` 分开：表单层只做字段绑定，校验与业务规则在 service。

### 3. 图片上传

```
POST /api/v1/menu/recipes/images（multipart file）或页面表单的 imageFile
  → RecipeService.uploadImage(MultipartFile)
  → ImageStorage 接口 → ImageStorageService.store（本地磁盘 app.upload.dir，默认 uploads/）
  → 返回 URL（WebConfig 把 /uploads/** 映射到该目录，页面直接 <img th:src="${r.imageUrl}">）
```

### 4. 下架菜品（逻辑删除）

```
POST /recipes/{id}/delete（页面「停用」→ RecipePageController.disable）或 API DELETE /api/v1/menu/recipes/{recipeId}
  → RecipeService.disable(recipeId, reason)
  → RecipeServiceImpl
       1) countMenusReferencing(recipeId, PUBLISHED) > 0 → 42203 DATA_PROTECTED
          （已发布菜单引用了该菜品，必须先下架菜单，避免历史菜单/订单口径被破坏）
       2) status=DISABLED + offline_reason → saveAndFlush → RecipeChangedEvent(DISABLED)
  → 返回受影响的草稿菜单数（页面提示）
```

### 5. 菜单列表 / 编辑 / 复制

```
GET /menus → MenuPageController.list → MenuService.page → MenuRepository + MenuItemRepository(批量取明细) → menu/list.html
GET /menus/new、/menus/{id}/edit → MenuForm（rows 为菜品勾选+菜单价）
POST /menus/save
  → MenuService.createDraft(cmd) / update(menuId, cmd)
  → MenuServiceImpl
       1) createDraft：status=DRAFT、version=0、created_by=当前用户
       2) buildMenuItems：按 recipeId 取菜品，快照 菜名/分类/单位/图片 写入 menu_item，
          售价取 menuPrice ?: 菜品标准价（菜单级调价在这里生效）
       3) update：仅 DRAFT 可改（40902）+ @Version 校验；先 deleteAllByMenuId 再重建明细
POST /menus/{id}/copy（复制历史菜单）
  → MenuPageController.copy：读源菜单（已发布菜单读到的是快照明细）
  → 组装 MenuCreateCmd（名称 + "（副本）"，售价沿用快照/菜单价）→ MenuService.createDraft
```

### 6. 发布菜单（快照冻结，核心不变量）

```
POST /menus/{id}/publish（页面/`POST /api/v1/menu/menus/{menuId}/publish`）
  → MenuService.publish(menuId)
  → MenuServiceImpl
       1) 仅 DRAFT 可发布（40902）
       2) 菜单明细不能为空
       3) validatePublishable：明细里的菜品必须仍为 ACTIVE（下架菜品不能发布）
       4) menu.status=PUBLISHED、locked=true、published_at=now → saveAndFlush
       5) MenuSnapshotService.freeze(menuId)：把菜名/分类/单位/标准价/菜单价写入 menu_snapshot（只插不改）
       6) 发布 MenuPublishedEvent(menuId, version, effectiveDate, snapshotCount)
  → 返回 PublishResultVO（状态、发布时间、快照条数、版本号）
```

发布后菜单锁定：既不能改也不能删，只能下架；要调整就用「复制为草稿」生成新菜单。

### 7. 下架菜单

```
POST /menus/{id}/offline → MenuPageController.unpublish → MenuService.unpublish(menuId, reason)
  → 仅 PUBLISHED 可下架 → status=OFFLINE、offline_at、offline_reason（locked 仍保持 true）
  → 快照、历史订单均不受影响
```

页面上还有「复制」和「下架草稿」两个按钮：复制见上一节；`POST /menus/{id}/delete`
（`MenuPageController.delete`）同样调用 `unpublish(id, "页面删除草稿")`，见文末“已知问题”。

### 8. 下单取价（跨模块契约，M2 调用）

```
OrderServiceImpl.requirePublishedMenu(date)
  → MenuService.getCurrent(date)
  → MenuServiceImpl
       1) 取 status=PUBLISHED 且 effective_date <= date 的菜单（按生效日期倒序）
       2) 读 menu_snapshot；无快照的菜单跳过，继续找上一份可用菜单
       3) 用快照值组装 MenuVO（菜名/分类/单位/价格/图片）
  → 下单时把快照价写入 order_detail（见 02 文档）
```

> 这是 M2 唯一的取价入口（`AGENTS.md` 2.3），菜品/菜单后续改名调价都不会影响已发布菜单与历史订单。

### 9. 分类字典

```
GET /api/v1/menu/recipes/categories → RecipeService.listCategories
  → RecipeRepository.findDistinctCategories（按 recipe.category 去重派生）
  → CategoryVO(categoryId=名称稳定哈希, category, 菜品数)
```

M3 生产单按分类聚合时复用该分类字典（跨模块契约 `RecipeService.listCategories`）。

## 六、跨模块依赖与事件

| 方向 | 对象 | 用途 |
| --- | --- | --- |
| 被 M2 调用 | `MenuService.getCurrent(LocalDate)` | 下单取当日已发布菜单与快照价（唯一取价入口） |
| 被 M3 调用 | `RecipeService.listCategories()` | 生产单按分类聚合 |

## 七、关键不变量

1. **快照只插不改**：`menu_snapshot` 在发布时写入，之后任何菜品/菜单改动都不回写快照。
2. **发布即锁定**：`PUBLISHED`/`OFFLINE` 的菜单 `locked=true`，不可改不可删，只能复制为新草稿。
3. **菜品逻辑下架**：不做物理删除；被已发布菜单引用时禁止下架（42203）。
4. **乐观锁**：菜品、菜单都用 `@Version`，页面表单回传 version，冲突 40902。
5. **分类字典派生**：分类来自 `recipe.category` 去重，`categoryId` 为名称稳定哈希，暂不单独建表。
